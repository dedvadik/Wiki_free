# Папка `custom/` — глубокая кастомизация

Эта папка монтируется в контейнер как `/app/custom` (только чтение), и файлы в ней **имеют приоритет** над встроенными. Код приложения менять не нужно.

```text
custom/
├── views/          ← шаблоны EJS: файл с тем же путём заменяет встроенный из views/
│   └── partials/
│       └── footer.ejs
├── public/         ← статика, доступна по адресу /<путь>
│   ├── custom.css  ← если файл есть, подключается на всех страницах
│   ├── custom.js   ← если файл есть, подключается на всех страницах
│   ├── img/logo.svg← перекрывает стандартный логотип
│   └── themes/     ← свои темы оформления: themes/<id>/theme.json + theme.css
│                     (см. public/themes/README.md в корне проекта)
└── examples/       ← готовые примеры (сами по себе НЕ подключаются)
```

## Как заменить шаблон

1. Найдите нужный файл в папке `views/` проекта, например `views/partials/footer.ejs`.
2. Скопируйте его в `custom/views/partials/footer.ejs` и отредактируйте копию.
3. Перезапустите приложение: `docker compose restart app`.

Шаблоны подключают друг друга по абсолютным путям (`include('/partials/header')`), поэтому переопределить можно даже отдельный кусочек страницы.

## Как добавить свои стили или скрипт

Создайте `custom/public/custom.css` и/или `custom/public/custom.js`, затем перезапустите приложение. Файлы подключатся на всех страницах после встроенных, поэтому переопределяют их.

Для небольших правок CSS перезапуск не нужен: используйте поле «Собственный CSS» в **Администрирование → Оформление**.

> Скрипты работают только из файлов (политика безопасности CSP запрещает встроенные `<script>`), поэтому свой JavaScript кладите именно в `custom.js`.

## Примеры

В `custom/examples/` лежат готовые файлы. Чтобы включить пример, скопируйте его в нужное место:

```bash
mkdir -p custom/public custom/views/partials
cp custom/examples/custom.css custom/public/custom.css
cp custom/examples/footer.ejs custom/views/partials/footer.ejs
docker compose restart app
```
