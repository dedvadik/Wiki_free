Всё, что администратор меняет в интерфейсе (название, доступ, тема, цвета, LDAP), описано одной декларативной схемой. По ней строятся формы админки, проверяются значения и генерируется CSS.

## Схема настроек: SETTINGS_SCHEMA

Файл `src/services/settings.js`. Каждая настройка — объект:

```javascript
{ tab: 'access', group: 'Доступ и права', key: 'require_login',
  label: 'Закрытая вики: читать могут только вошедшие пользователи',
  type: 'bool', default: false }
```

| Поле | Назначение |
| --- | --- |
| `key` | имя; в шаблонах доступно как `site.<key>` |
| `tab` | раздел админки: `general` (по умолчанию), `access`, `appearance`, `ldap`; каждый раздел — отдельная страница |
| `group` | заголовок карточки внутри раздела |
| `label`, `help` | подпись и подсказка |
| `type` | тип поля (таблица ниже) |
| `default` | значение по умолчанию |
| `options` | для `select`: `[[значение, подпись], …]` |
| `min`, `max` | для `number` |
| `optional` | для `color`/`number`: пусто = «как в теме» |
| `pattern`, `patternError` | для `text`: проверка формата (адрес LDAP, фильтр) |

| Тип | Элемент формы | Проверка |
| --- | --- | --- |
| `text` | строка | обрезка пробелов, до 500 символов, `pattern` |
| `textarea`, `markdown`, `code` | многострочное поле | `\r\n` → `\n`, до 50 000 символов |
| `url` | строка | пусто, `/путь` или `http(s)://` (без `javascript:`) |
| `bool` | переключатель iOS | `on`/`true`/`1` → `true` |
| `color` | палитра + текст | строго `#rgb` / `#rrggbb` |
| `select` | список | значение из `options` |
| `number` | число | «прижимается» к диапазону `min…max` |
| `theme` | карточки тем с превью | тема есть в реестре |
| `secret` | пароль | в HTML не выводится никогда |

## Жизненный цикл значения

```text
default в схеме
   ▲ перекрывается
SETTING_<КЛЮЧ> из окружения (пустое значение = не задано)
   ▲ перекрывается
значение из таблицы settings (сохранено в админке)
```

- **`loadSettings()`** при старте читает таблицу `settings` в кэш `Map` в памяти. Поэтому `getSettings()` на каждом запросе ничего не стоит.
- **`updateSettings(input, keys)`** сначала проверяет **все** значения через `normalizeValue`. При любой ошибке ничего не сохраняется и возвращается список ошибок. Иначе значения записываются одной транзакцией (UPSERT), обновляются кэш и «версия» настроек.
- **`keysForTab(tab)`** — ключи раздела. Сохранять нужно только поля, которые есть в форме: отсутствующий чекбокс означает «выключено», и чужие разделы иначе сбросились бы.
- **`resetSettings(group)`** удаляет строки группы из БД, и снова действуют умолчания.
- **Версия настроек** (`getSettingsVersion`) меняется при каждом сохранении и добавляется к ссылке `/theme.css?v=…`, поэтому браузеры сразу получают новые стили.

:::note Несколько копий приложения
Кэш настроек живёт в памяти процесса. Если запустить несколько копий за балансировщиком, после изменения настроек перезапустите остальные копии.
:::

### Секреты

Поле типа `secret` (пароль служебной учётной записи LDAP):

- в `getSettings()`, а значит и в шаблонах (`site.*`), заменено пустой строкой — даже переопределённый шаблон не выведет его на страницу;
- читается только кодом сервера через `getSecret(key)`; `hasSecret(key)` сообщает форме, что пароль сохранён;
- пустое поле при сохранении означает «оставить как есть».

## Как админка строит формы

`routes/admin.js` → `renderSection(section)` → шаблон `views/admin/settings.ejs` → partial `views/partials/settings-groups.ejs`. Partial проходит по группам схемы раздела и для каждого поля выбирает элемент по типу. Разделы описаны в объекте `SETTINGS_SECTIONS` (название, иконка, описание):

| Раздел | Адрес | Группы |
| --- | --- | --- |
| Общие | `/admin/settings/general` | «Общие»: название, логотип, приветствие, объявление, подвал |
| Доступ и права | `/admin/settings/access` | закрытая вики, регистрация, роль по умолчанию, комментарии |
| Оформление | `/admin/settings/appearance` | «Тема оформления», «Цвета и шрифты», «Интерфейс» (мигающий курсор только в редакторе, редактор страниц по умолчанию) |
| LDAP | `/admin/ldap` | подключение, поиск пользователей, атрибуты и роли (свой маршрут из-за кнопки проверки) |

Итог: **добавили объект в схему — поле появилось в админке**, прошло проверку и стало доступно в шаблонах. Рецепт — на странице [Как расширять портал](page:Как расширять портал).

## /theme.css — CSS из настроек

`src/services/theme.js → buildThemeCss(settings)` генерирует маленький файл, который подключается **после** базового CSS и темы оформления:

```css
:root,
:root[data-mode="dark"] {
  --primary: #e60023;          /* только если поле заполнено */
  --content-font-size: 16px;   /* параметры раскладки — всегда */
  --content-max: 960px;
  --sidebar-width: 280px;
}
/* ---------- Пользовательский CSS из админ-панели ---------- */
```

- Выводятся **только заполненные** переопределения. Пустое поле означает «как в теме», и действует значение выбранной темы.
- Переменные пишутся сразу для `:root` и `:root[data-mode="dark"]`: второй селектор специфичнее, и без него тёмный режим темы перекрыл бы фирменный цвет из админки.
- В конец добавляется поле «Собственный CSS».
- Кэширование: при совпадении `?v=` с текущей версией отдаётся `Cache-Control: immutable`, иначе `no-cache`.

Значения попадают в CSS только после `normalizeValue` (цвет строго `#RRGGBB`, числа в диапазоне), поэтому внедрить через них посторонний CSS нельзя.

## Цветовые пресеты

`THEME_PRESETS` — кнопки «Confluence», «Лес», «Виноград»… в разделе «Оформление». Они заполняют поля цветов через `public/js/admin.js`; сохраняются значения только кнопкой «Сохранить». Первый пресет, «Цвета темы», очищает поля.
