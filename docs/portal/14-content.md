## Markdown → безопасный HTML (services/markdown.js)

Главная функция — `renderMarkdown(source)` → `{ html, toc }`. Её используют страница статьи, старая версия, комментарии, описание пространства, приветствие на главной и предпросмотр в редакторе. Поэтому предпросмотр **всегда совпадает** с результатом.

```text
текст → marked.parse (GFM + макросы + подсветка кода + id заголовков)
      → sanitize-html (белый список)
      → замена маркера [[toc]] на готовое оглавление
```

### Макросы (расширения marked)

| Синтаксис | Расширение | Результат |
| --- | --- | --- |
| `:::info Заголовок` … `:::` | `panelExtension` (блочное) | цветная панель; типы `info`, `note`, `tip`, `success`, `warning`, `error` |
| `[[toc]]` на отдельной строке | `tocExtension` | оглавление страницы |
| `{{status:green:ГОТОВО}}` | `statusExtension` (строчное) | цветной статус; цвета `grey`, `red`, `yellow`, `green`, `blue`, `purple` |

Устройство расширения: `start(src)` подсказывает парсеру, где может начаться конструкция, `tokenizer(src)` превращает текст в токен (содержимое панели разбирается как обычный Markdown через `this.lexer.blockTokens`), `renderer(token)` выдаёт HTML.

:::tip Почему в статусе двоеточие, а не «|»
В GFM-таблицах вертикальная черта разделяет ячейки. Синтаксис `{{status:green|OK}}` «разрывал» бы строку таблицы, а таблицы статусов — главный сценарий этого макроса.
:::

### Заголовки и оглавление

Переопределённый `renderer.heading` даёт каждому заголовку `id` из текста (`h-установка`; кириллица сохраняется) и добавляет якорь `#`. Одинаковые заголовки получают суффиксы `-1`, `-2`. Параллельно заголовки собираются в `toc`. Состояние текущего рендера лежит в переменной модуля `renderState`: `marked` работает синхронно, а JavaScript однопоточен, поэтому два рендера не перемешаются. Маркер `[[toc]]` заменяется оглавлением **после** очистки HTML, так как оглавление строится из уже экранированного текста.

### Подсветка кода

`marked-highlight` + `highlight.js` на сервере: читателю не нужно загружать никакого JavaScript. Цвета классов `hljs-*` заданы CSS-переменными, поэтому подсветка работает и в светлом, и в тёмном режиме.

### excerpt(markdown, length)

Короткий фрагмент текста без разметки для списков, результатов поиска и страниц меток. Из текста удаляются блоки кода, картинки, панели, символы Markdown и разделители таблиц.

## Дерево страниц (services/pages.js)

| Функция | Что делает |
| --- | --- |
| `pageUrl(page)` | `/pages/42/название-страницы`; главный идентификатор — id, слаг только для читаемости |
| `getSpaceTree(spaceId)` → `buildTree(rows)` | все страницы пространства одним запросом → дерево за один проход (`Map` по id) |
| `flattenTree(tree, excludeId)` | плоский список с глубиной для выбора родителя; исключает страницу и её поддерево |
| `getAncestors(pageId)` | цепочка родителей для хлебных крошек (рекурсивный CTE) |
| `isDescendant(pageId, candidateId)` | защита от цикла при смене родителя |
| `parseLabels`, `setPageLabels` | нормализация меток и их сохранение; «осиротевшие» метки удаляются |
| `linkAttachments` | привязка файлов, загруженных до первого сохранения новой страницы |
| `readPageForm(body)` | разбор и проверка формы редактора (`\r\n` → `\n`!) |

## Жизненный цикл страницы (routes/pages.js)

### Создание

`POST /spaces/:key/pages` одной транзакцией создаёт строку `pages`, версию 1 в `page_versions`, метки и привязку вложений.

### Редактирование и оптимистичная блокировка

Форма редактора содержит `base_version` — номер версии, которую человек открыл. Сохранение:

```sql
UPDATE pages SET title = $2, content = $3, …, version = version + 1
 WHERE id = $1 AND version = $7   -- $7 = base_version
 RETURNING version
```

- **1 строка** → записываем новую версию в `page_versions`.
- **0 строк** → кто-то уже сохранил страницу. Ответ `409`: редактор открывается снова с **текстом пользователя** (он не теряется), предупреждением и ссылкой на чужие изменения. Повторное сохранение перезапишет страницу осознанно.

Новая версия создаётся, только если изменились заголовок или текст. Перемещение в дереве и смена меток версию не увеличивают.

### История, сравнение, откат

- `/pages/:id/history` — таблица версий; радиокнопки «от/до» выбирают пару для сравнения.
- `/pages/:id/diff` → `services/diff.js → buildLineDiff(old, new, context = 3)`: библиотека `diff` находит изменённые фрагменты; строки нумеруются, длинные неизменённые участки сворачиваются в «⋯ без изменений: N стр.».
- `POST …/versions/:v/restore` **не удаляет историю**, а создаёт новую версию с содержимым старой, поэтому можно «откатить откат».

### Удаление

По умолчанию дочерние страницы переходят к родителю удаляемой. С флажком «вместе с дочерними» удаляется всё поддерево (рекурсивный CTE). Версии, комментарии и избранное удаляются каскадно.

### Просмотр

`GET /pages/:id{/:slug}` одновременно (`Promise.all`) загружает пространство, дерево, предков, дочерние страницы, метки, комментарии, вложения и отметку избранного. Устаревший слаг (страницу переименовали) → `301` на актуальный адрес, так старые ссылки продолжают работать.

## Поиск (routes/home.js)

```sql
WITH q AS (SELECT websearch_to_tsquery('russian', $1) AS query)
SELECT …,
       ts_rank(p.search_vector, q.query)
         + CASE WHEN p.title ILIKE $2 THEN 1 ELSE 0 END AS rank,
       ts_headline('russian', p.content, q.query,
         'StartSel=⟦, StopSel=⟧, MaxWords=35, MinWords=15, MaxFragments=2') AS snippet
  FROM pages p … CROSS JOIN q
 WHERE (p.search_vector @@ q.query OR p.title ILIKE $2)
 ORDER BY rank DESC, p.updated_at DESC LIMIT 50
```

- `websearch_to_tsquery` понимает синтаксис поисковиков: `"точная фраза"`, `docker or kubernetes`, `-исключить`.
- `ILIKE` по заголовку находит и частично набранные слова. Спецсимволы `%` и `_` экранируются.
- Фрагменты с совпадениями размечаются маркерами `⟦ ⟧`. Сначала весь фрагмент экранируется, потом маркеры заменяются на `<mark>`, поэтому подсветка безопасна. Если обрезка «съела» закрывающий маркер, он дописывается.

## Метки, комментарии, избранное, экспорт

- **Метки** вводятся через запятую или пробел, приводятся к нижнему регистру (разрешены буквы, цифры, `-`, `_`), не больше 20 на страницу.
- **Комментарии** хранятся в Markdown и рендерятся той же функцией; удалить комментарий может автор или администратор; раздел отключается настройкой `allow_comments`.
- **Избранное** — переключатель: `DELETE`, а если ничего не удалено — `INSERT`.
- **Экспорт** `/pages/:id/export.md`: `res.attachment()` корректно кодирует кириллицу в имени файла.
