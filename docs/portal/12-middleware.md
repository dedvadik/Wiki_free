Middleware выполняются для каждого запроса (порядок — на странице [Запуск и обработка запроса](page:Запуск и обработка запроса)). Все четыре файла лежат в `src/middleware/`.

## auth.js — кто пользователь и что ему можно

| Функция | Что делает |
| --- | --- |
| `loadUser` | по `req.session.userId` загружает пользователя из БД **на каждом запросе**. Поэтому блокировка или смена роли действует сразу, а не после повторного входа. Заблокированный или удалённый пользователь «разлогинивается» |
| `requireLogin` | только для вошедших: гостя запоминает (`session.returnTo`) и отправляет на `/login`, для `/api/*` отвечает 401 |
| `requireRole('editor')` | роль editor **или выше**; вошедший без прав получает 403 |
| `siteAccess` | если включена «закрытая вики», всё, что подключено после него, требует входа |

Роли упорядочены уровнями (`services/users.js`): `viewer: 1`, `editor: 2`, `admin: 3`. Проверка `hasRole(user, role)` сравнивает уровни.

## csrf.js — защита форм

- `getCsrfToken(req)` — лениво создаёт токен в сессии.
- `csrfProtection` — пропускает `GET`/`HEAD`/`OPTIONS`; для остальных методов берёт токен из `req.body._csrf` или заголовка `X-CSRF-Token` и сравнивает за постоянное время.

У multipart-запросов (загрузка файлов) тело на этом этапе ещё не разобрано, поэтому для них токен ожидается в заголовке.

## locals.js — переменные для всех шаблонов

Всё, что лежит в `res.locals`, доступно в любом EJS-шаблоне без явной передачи. `baseLocals(req)` собирает:

| Переменная | Что это |
| --- | --- |
| `site` | все настройки сайта (секреты заменены пустыми строками) |
| `activeTheme`, `themePreview` | тема оформления этого запроса и признак предпросмотра |
| `themeVersion`, `assetVersion` | версии для сброса кэша: `/theme.css?v=…`, `/css/app.css?v=…` |
| `customAssets` | есть ли `custom/public/custom.css` и `custom.js` (проверяется при старте) |
| `currentUser`, `currentPath`, `searchQuery` | текущий пользователь, путь, строка поиска |
| `can(role)` | есть ли у пользователя роль: `<% if (can('editor')) { %>` |
| `csrfToken()` | токен для скрытого поля форм |
| `consumeFlashes()` | забрать и удалить накопленные уведомления |
| `formatDate`, `timeAgo`, `fileSize`, `plural`, `authorName`, `avatarHue` | форматирование (`utils/format.js`) |
| `initials`, `icon`, `pageUrl`, `roleNames` | инициалы, SVG-иконки, адрес страницы, названия ролей |

### Выбор темы для запроса (resolveTheme)

1. `?theme=<id>` в адресе — **предпросмотр** (только эта страница, ничего не сохраняется);
2. тема из профиля пользователя, если выбор тем разрешён;
3. тема сайта из настроек;
4. «Классическая», если выбранную тему удалили из папки.

### Flash-уведомления

`req.flash('success' | 'error' | 'info', текст)` кладёт сообщение в сессию. Шапка сайта забирает его через `consumeFlashes()` при ближайшей отрисовке страницы, то есть уже после редиректа.

## errors.js — 404 и обработчик ошибок

- `notFound` превращает «ни один маршрут не подошёл» в `HttpError(404)`.
- `errorHandler(err, req, res, next)` (именно четыре параметра — так Express отличает обработчик ошибок):
  - определяет статус: из `HttpError`, из ошибок библиотек, `LIMIT_FILE_SIZE` → 413, иначе 500;
  - серверные ошибки (5xx) пишет в журнал со стеком;
  - в production скрывает детали 500-х ошибок;
  - для `/api/*` отвечает JSON, иначе рендерит `views/error.ejs`;
  - если ошибка случилась до `locals` (например, упала БД при загрузке сессии), сам дозаполняет переменные;
  - если не отрисовался даже шаблон ошибки, отдаёт простой текст.
