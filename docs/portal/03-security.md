## XSS: как статья становится безопасным HTML

```text
Markdown пользователя
   │  marked (+ макросы, подсветка кода)
   ▼
«сырой» HTML — может содержать <script>, onclick, javascript:
   │  sanitize-html (белый список тегов, атрибутов, протоколов)
   ▼
безопасный HTML → выводится в шаблоне через <%- %>
```

Белый список (`SANITIZE_OPTIONS`) разрешает стандартные теги форматирования, таблицы, `img`, `details`/`summary`, `kbd`, `mark`, а из атрибутов — только `id`, `class`, `title`, `href`/`src` и немного специфичных (`checked` у чекбоксов задач, `align` у ячеек). Атрибуты `style` и `on*` удаляются, протоколы ссылок — только `http`, `https`, `mailto`, `tel`. Внешние ссылки получают `target="_blank" rel="noopener noreferrer"`.

Даже если очистка когда-нибудь пропустит скрипт, **CSP** (`script-src 'self'`) не даст ему выполниться. Встроенных `<script>` в шаблонах нет: весь JavaScript лежит в файлах `public/js/`.

## CSRF: как это работает

1. В сессии хранится случайный токен (32 байта). Создаётся он **лениво**, только когда шаблон вызывает `csrfToken()`, поэтому анонимные читатели не порождают записей сессий.
2. Каждая форма содержит `<input type="hidden" name="_csrf">`, а JS-запросы (`fetch` в редакторе) передают заголовок `X-CSRF-Token` из `<meta name="csrf-token">`.
3. Любой `POST`/`PUT`/`PATCH`/`DELETE` без правильного токена получает 403. Сравнение идёт через `crypto.timingSafeEqual`.

Выход из системы тоже сделан через `POST` с токеном, чтобы чужой сайт не мог «разлогинить» пользователя картинкой `<img src="/logout">`.

## Пароли

- **bcrypt** (`bcryptjs`, стоимость `BCRYPT_ROUNDS`, по умолчанию 10) — медленная функция с солью.
- Длина от 8 символов и **не более 72 байт**: bcrypt учитывает только первые 72 байта, поэтому более длинные пароли отклоняются, а не обрезаются молча.
- Если пользователь не найден, `checkLocalPassword` всё равно сравнивает пароль с фиктивным хешем (`DUMMY_HASH`), чтобы по времени ответа нельзя было понять, существует ли логин.

## Файлы

- На диск файл пишется под случайным именем `UUID + расширение`: через имя нельзя перезаписать чужой файл или выйти из папки.
- `inline` показываются только растровые картинки (`.png .jpg .gif .webp .avif .bmp .ico`) с MIME `image/*`. SVG и HTML всегда скачиваются.
- Ответ содержит `Content-Security-Policy: default-src 'none'; …; sandbox` и `X-Content-Type-Options: nosniff`.
- В закрытой вики файлы тоже требуют входа: маршрут подключён после `siteAccess`.

## Что стоит сделать при развёртывании

:::tip Чек-лист
- Задайте свой `POSTGRES_PASSWORD` до первого запуска.
- Задайте `ADMIN_PASSWORD` (не короче 8 символов) или сразу зарегистрируйтесь сами: первый пользователь становится администратором.
- Для доступа из интернета поставьте HTTPS-прокси и включите `TRUST_PROXY=1`, `COOKIE_SECURE=true`.
- Не публикуйте порт PostgreSQL наружу: в `docker-compose.yml` он намеренно закрыт.
- Настройте резервное копирование базы и volume с вложениями, см. [Развёртывание в Docker](page:Развёртывание в Docker).
:::
