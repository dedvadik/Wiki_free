# Нагрузочное тестирование WikiSpace

Сценарии для [k6](https://k6.io). Результаты последнего прогона и выводы есть на портале, в пространстве «Код портала» → «Нагрузочное тестирование» (файл `docs/portal/31-load-testing.md`).

| Файл | Что проверяет |
| --- | --- |
| `lib.js` | общие функции: вход, CSRF, список тестовых страниц, сводка |
| `read-capacity.js` | предел пропускной способности на чтение: VUS пользователей читают без пауз |
| `users.js` | сколько людей могут работать одновременно: вход, чтение, поиск, комментарии, правки, паузы «на чтение» |
| `spike.js` | резкий наплыв пользователей и восстановление после него |
| `uploads.js` | какие файлы и какого размера принимаются, параллельные загрузки |

## 1. Тестовый стенд

Не запускайте нагрузку на рабочий портал: отдельный проект Compose поднимается рядом и не мешает основному.

```bash
# Стенд на порту 18080. Лимит попыток входа поднят: весь трафик k6 идёт с одного IP.
APP_PORT=18080 ADMIN_PASSWORD=Admin12345 POSTGRES_PASSWORD=testpass AUTH_RATE_LIMIT=100000 \
  docker compose -p wikitest up -d --build

# Данные: 1000 пользователей, 50 пространств, 20 000 страниц (~35 с)
docker compose -p wikitest exec app node src/tools/seed-load.js --yes
```

Параметры генератора (`--users`, `--spaces`, `--pages`) и удаление данных (`--clean`) описаны в начале `src/tools/seed-load.js`.

## 2. Запуск сценариев

k6 запускается в Docker в той же сети, что и стенд, и обращается к нему по адресу `http://app:3000`:

```bash
k6() { docker run --rm -i --network wikitest_default -v "$PWD/tests/load:/scripts" grafana/k6 run "$@"; }

k6 -e VUS=20 -e DURATION=60s /scripts/read-capacity.js
k6 -e USERS=500 -e RAMP=2m -e HOLD=3m /scripts/users.js
k6 -e BASE_USERS=50 -e SPIKE=800 /scripts/spike.js
k6 -e UPLOADERS=10 -e UPLOAD_MB=5 /scripts/uploads.js
```

В начале каждого запуска `setup()` обходит дерево страниц (10–30 секунд) и печатает строку `-e PAGE_RANGES=…`. Передайте её в следующие запуски, чтобы пропустить обход.

Сводка в конце показывает запросы в секунду, долю ошибок и задержки по типам запросов (p50/p95/p99). Если смонтировать папку и передать `-e OUT_DIR=/out`, полная сводка сохранится в JSON.

Во время теста полезно смотреть `docker stats`: упор в ~100% CPU у контейнера `app` означает, что процесс Node.js загружен полностью. Он использует одно ядро процессора.

## 3. Уборка

```bash
docker compose -p wikitest down -v   # стенд вместе с данными
```
