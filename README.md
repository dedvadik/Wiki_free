# WikiSpace — база знаний в стиле Confluence

Self-hosted сайт для публикации статей и документации: пространства, дерево страниц, история версий, поиск, комментарии, вложения, авторизация с ролями и гибкая настройка внешнего вида. Упакован в Docker и собирается под **amd64, arm64 и arm/v7**.

## Возможности

| Область | Что есть |
| --- | --- |
| **Структура** | Пространства (разделы с ключом, иконкой, цветом) → дерево страниц любой вложенности, хлебные крошки, дочерние страницы |
| **Редактор** | Markdown с панелью инструментов, живым предпросмотром, горячими клавишами (Ctrl+S/B/I/K), вставкой картинок из буфера и drag&drop |
| **Макросы** | Панели `:::info / note / tip / success / warning / error`, оглавление `[[toc]]`, статусы `{{status:green:ГОТОВО}}`, подсветка кода, списки задач, таблицы |
| **Версии** | Полная история, просмотр любой версии, построчное сравнение (diff), откат, защита от одновременного редактирования |
| **Поиск** | Полнотекстовый поиск PostgreSQL с русской морфологией, подсветка совпадений, фильтр по пространству |
| **Совместная работа** | Комментарии, метки, избранное, лента изменений, экспорт в Markdown |
| **Авторизация** | Регистрация/вход, **LDAP / Active Directory** с ролями по группам, роли «Читатель / Редактор / Администратор», блокировка, закрытый режим «только для вошедших» |
| **Темы оформления** | «Классическая» (Confluence) и «iCloud», светлый и тёмный режим, выбор темы администратором и каждым пользователем, свои темы в `custom/` |
| **Кастомизация** | Админ-панель (цвета поверх темы, пресеты, шрифт, ширина, логотип, свой CSS…), переменные окружения, переопределение любых шаблонов через папку `custom/` |
| **Безопасность** | bcrypt, CSRF-токены, CSP, очистка HTML от XSS, защита от перебора паролей, фиксации сессии и open redirect |

## Быстрый старт

Нужен только Docker (Docker Desktop на Windows/macOS или Docker Engine + Compose на Linux).

```bash
# 1. Настройки развёртывания
cp .env.example .env
#    откройте .env и задайте POSTGRES_PASSWORD и ADMIN_PASSWORD (не короче 8 символов)

# 2. Сборка и запуск
docker compose up -d --build

# 3. Откройте http://localhost:8080 и войдите как admin
```

Если `ADMIN_PASSWORD` не задан, администратором станет **первый зарегистрировавшийся** пользователь.

Полезные команды:

```bash
docker compose logs -f app       # логи приложения
docker compose restart app       # перезапуск (например, после правок в custom/)
docker compose down              # остановить (данные сохраняются в volumes)
docker compose down -v           # остановить и УДАЛИТЬ все данные
```

```text
│   ├── server.js            # точка входа: миграции, инициализация, запуск, graceful shutdown
│   ├── app.js               # цепочка middleware и подключение маршрутов
│   ├── config.js            # все переменные окружения в одном месте

│   │   ├── pool.js          # пул соединений PostgreSQL, транзакции

│   │   └── migrations/      # 001_init.sql — схема БД
│   ├── middleware/          # auth (роли), csrf, locals (переменные шаблонов), errors
│   ├── routes/              # auth, home (главная/поиск/метки), spaces, pages, uploads, admin, profile, api
│   ├── services/            # бизнес-логика: settings, themes, markdown, pages, users, auth, ldap, diff, theme, bootstrap
│   ├── seed/                # тексты демо-страниц
│   └── utils/               # HTTP-помощники, форматирование дат и размеров
├── views/                   # EJS-шаблоны (partials/ — шапка, подвал, дерево страниц…)
├── public/                  # CSS, клиентский JS (режим, редактор, админка), иконки
│   └── themes/              # темы оформления: classic/, icloud/ (theme.json + theme.css)
├── custom/                  # ВАШИ переопределения шаблонов и статики (см. custom/README.md)
└── docs/portal/             # техническая документация кода — публикуется на сам портал
```

### Документация кода — на самом портале

Подробное описание всего кода (архитектура, база данных, безопасность, все маршруты, сервисы, шаблоны, стили и темы, клиентский JS, Docker, рецепты доработок) лежит в `docs/portal/*.md`. Команда импорта публикует его на портал как пространство **«Код портала»** (ключ `CODE`):

```bash
docker compose exec app npm run docs:import
```

Импорт можно запускать повторно: изменившиеся страницы получают новую версию в истории, неизменившиеся не трогаются. Правьте документацию в репозитории вместе с кодом.

Каждый файл подробно прокомментирован: в начале — назначение модуля, перед каждым блоком — что он делает и почему именно так.

### Как обрабатывается запрос

```text
Браузер → helmet (CSP) → статика (custom/public, public)
        → разбор формы/JSON → сессия (PostgreSQL) → пользователь → CSRF
        → /healthz, /theme.css, /login, /register     ← доступны всегда
        → siteAccess (закрытая вики?)
        → главная, пространства, страницы, файлы, профиль, админка
        → 404 / обработчик ошибок
```

## Профиль, настройки и администрирование

В меню аватара три отдельных раздела. У «Настроек» и «Администрирования» одинаковое оформление в стиле «Системных настроек» macOS: слева меню разделов с цветными значками, справа страница выбранного раздела.

| Раздел | Что там |
| --- | --- |
| **Профиль** (`/profile`) | Визитка: обложка, аватар, роль; статистика (страницы, правки, комментарии, избранное); сведения об учётной записи; недавние правки и избранное. Только просмотр |
| **Настройки** (`/settings`) | «Учётная запись» — имя и email; «Безопасность» — смена пароля и кнопка «Выйти на всех других устройствах»; «Оформление» — своя тема, светлый/тёмный режим и вид редактора по умолчанию |
| **Администрирование** (`/admin`, только админы) | «Обзор» — статистика, новые пользователи, сведения о системе; «Общие», «Доступ и права», «Оформление» — настройки сайта (каждый раздел сохраняется отдельно); «LDAP»; «Пользователи» |

У каждого пользователя свой цвет аватара: он вычисляется из имени и одинаков на всех страницах.

## Роли

| Роль | Права |
| --- | --- |
| Читатель | Просмотр, поиск, комментарии, избранное |
| Редактор | + создание и правка пространств и страниц, загрузка файлов, откат версий |
| Администратор | + настройки сайта, управление пользователями, удаление пространств |

Роль новых пользователей задаётся в настройках. Администратор может менять роли, блокировать пользователей (их сеансы сразу завершаются), сбрасывать пароли и **удалять** учётные записи: в карточке пользователя есть блок «Удаление», для подтверждения нужно ввести логин. Статьи, правки, комментарии и вложения удалённого пользователя сохраняются с подписью «удалённый пользователь». Удалить себя, а также удалить или понизить последнего администратора нельзя. LDAP-пользователя при следующем входе создадут заново, поэтому, чтобы закрыть ему доступ, лучше заблокируйте его.

## Вход через LDAP / Active Directory

Настраивается в **Администрирование → LDAP** (или переменными `SETTING_LDAP_*` в `.env`). Там же есть кнопка **«Проверить»**: она по шагам проверяет подключение, служебную учётную запись, поиск пользователя, атрибуты, роль по группам и пароль и объясняет, на каком шаге ошибка.

Как это работает:

1. Приложение входит **служебной учётной записью** (Bind DN) или анонимно и ищет пользователя по фильтру, например `(uid={{username}})`.
2. Пароль проверяется входом (bind) от имени найденной записи. Сайт пароль не хранит.
3. При первом входе учётная запись на сайте **создаётся автоматически**. Имя и email обновляются из каталога при каждом входе.
4. **Роли по группам:** участники группы администраторов получают роль «Администратор», группы редакторов — «Редактор», остальные — роль по умолчанию. Если группы заданы, роль пересчитывается при каждом входе. Поддерживаются `memberOf` (AD, OpenLDAP с overlay) и группы `groupOfNames` / `groupOfUniqueNames` / `posixGroup`.

| Параметр | OpenLDAP / FreeIPA | Active Directory |
| --- | --- | --- |
| Адрес | `ldap://ldap.example.com:389` | `ldaps://dc01.corp.example.com:636` |
| Bind DN | `cn=wiki,ou=service,dc=example,dc=com` | `wiki-svc@corp.example.com` |
| Base DN | `ou=people,dc=example,dc=com` | `ou=Users,dc=corp,dc=example,dc=com` |
| Фильтр | `(uid={{username}})` | `(&(objectClass=user)(sAMAccountName={{username}}))` |
| Атрибуты логин / имя | `uid` / `cn` | `sAMAccountName` / `displayName` |

Пускать только членов определённой группы можно фильтром: `(&(uid={{username}})(memberOf=cn=wiki-users,ou=groups,dc=example,dc=com))`.

Безопасность:

- **Локальная учётная запись приоритетнее.** Если на сайте есть локальный пользователь с таким же логином, LDAP для него не опрашивается. Пользователь каталога с логином `admin` не сможет войти в локального `admin`.
- **Локальные администраторы входят всегда**, даже если LDAP недоступен или локальный вход запрещён. Это аварийный доступ.
- Логин экранируется в фильтре по RFC 4515, так что LDAP-инъекции не пройдут. Пустой пароль отклоняется до обращения к серверу, иначе «анонимный bind» открыл бы любую учётную запись.
- Пароль служебной учётной записи никогда не выводится в HTML и шаблоны.
- LDAP-пользователи не меняют имя, email и пароль на сайте: это делается в каталоге.
- Для шифрования используйте `ldaps://` или STARTTLS. Проверку сертификата отключайте только для тестов.

## Темы оформления

Встроены две темы, у каждой есть светлый и тёмный режим (переключается кнопкой ◐ в шапке):

| Тема | Стиль |
| --- | --- |
| **Классическая** (по умолчанию) | в духе Confluence: синяя шапка, строгие карточки |
| **iCloud** | в духе iCloud.com: «стеклянная» полупрозрачная шапка, фон с мягким градиентом, белые карточки с крупными скруглениями, кнопки-«таблетки», шрифт SF Pro, тёмный режим в палитре macOS |

- Тему сайта выбирает администратор: **Администрирование → Оформление**. Выбор делается карточками с мини-превью.
- Если администратор разрешил, **каждый пользователь может выбрать свою тему**: **Настройки → Оформление** в меню аватара. Вариант «По умолчанию» следует за темой сайта.
- Ссылка «Предпросмотр» открывает страницу в выбранной теме без сохранения (`?theme=<id>` в адресе).
- Цвета, шрифт и скругление из настроек применяются **поверх любой темы**, если они заполнены. Так фирменный цвет компании задаётся один раз. Пустое поле означает «как в теме».
- **Своя тема** — папка `custom/public/themes/<id>/` с файлами `theme.json` и `theme.css`. Она появится в списке после перезапуска. Инструкция — в [public/themes/README.md](public/themes/README.md), готовый пример — [тема iCloud](public/themes/icloud/theme.css).

## Кастомизация

### 1. Админ-панель: без кода, применяется мгновенно

Разделы **Администрирование → Общие / Доступ и права / Оформление**:

- название, подзаголовок, логотип, favicon, текст подвала, баннер-объявление, приветствие на главной;
- закрытая вики, открытая регистрация, роль по умолчанию, комментарии;
- тема оформления сайта, выбор темы пользователями, светлый/тёмный режим по умолчанию;
- цветовые пресеты, основной цвет и цвета шапки поверх темы (с живым предпросмотром), шрифт, размер текста, ширина колонки и боковой панели, скругления;
- поле «Собственный CSS». В нём можно адресовать отдельную тему: `:root[data-ui-theme="icloud"] .topbar { … }`.

Форма строится автоматически по схеме `SETTINGS_SCHEMA` в [src/services/settings.js](src/services/settings.js). Добавили туда объект — поле появилось в админке, а значение стало доступно во всех шаблонах как `site.<ключ>`.

### 2. Переменные окружения: при развёртывании

См. таблицу ниже. Любую настройку из админки можно задать по умолчанию через `SETTING_<КЛЮЧ>`, например `SETTING_SITE_NAME="Вики отдела"` или `SETTING_REQUIRE_LOGIN=true`.

### 3. Папка `custom/`: полный контроль

Файлы из `custom/views` заменяют одноимённые шаблоны, `custom/public` — статику; `custom/public/custom.css` и `custom.js` подключаются автоматически. Подробности и примеры — в [custom/README.md](custom/README.md).

## Мультиплатформенная сборка

В проекте нет нативных модулей (драйвер `pg` и `bcryptjs` написаны на чистом JavaScript), поэтому образ собирается под любую архитектуру, где есть Node.js. Зависимости ставятся один раз на «родной» платформе сборщика и копируются в образы всех архитектур — эмуляция QEMU почти не нужна, сборка быстрая.

```bash
# Все платформы сразу с публикацией в реестр (amd64, arm64, arm/v7):
IMAGE=ghcr.io/you/wikispace TAG=1.0.0 docker buildx bake --push

# То же без bake:
docker buildx build --platform linux/amd64,linux/arm64,linux/arm/v7 \
  -t ghcr.io/you/wikispace:1.0.0 --push .
```

На другой машине (например, Raspberry Pi) укажите в `.env` `APP_IMAGE=ghcr.io/you/wikispace:1.0.0` и выполните `docker compose pull && docker compose up -d`: Docker сам скачает вариант под свою архитектуру. Какая архитектура реально запущена, видно в **Администрирование → Обзор**.

## Резервное копирование

```bash
# База данных
docker compose exec db pg_dump -U wiki wiki > backup.sql
# Вложения
docker compose cp app:/app/data ./data-backup

# Восстановление базы (в пустую БД)
docker compose exec -T db psql -U wiki wiki < backup.sql
```

## HTTPS и обратный прокси

Приложение слушает HTTP на порту 3000 внутри контейнера. Для HTTPS поставьте перед ним nginx, Caddy или Traefik и задайте в `.env`:

```dotenv
TRUST_PROXY=1
COOKIE_SECURE=true
```

## Как расширять

- **Новая настройка:** добавьте объект в `SETTINGS_SCHEMA` ([src/services/settings.js](src/services/settings.js)) и используйте `site.<ключ>` в шаблоне.
- **Изменение схемы БД:** создайте `src/db/migrations/002_<описание>.sql`. Он применится при следующем запуске. Старые миграции не редактируйте.
- **Новый макрос разметки:** добавьте расширение marked в [src/services/markdown.js](src/services/markdown.js) по образцу `panelExtension` и разрешите нужные теги/классы в `SANITIZE_OPTIONS`.
- **Новая кнопка редактора:** `<button data-md="имя">` в [views/pages/form.ejs](views/pages/form.ejs) плюс функция `имя` в объекте `ACTIONS` в [public/js/editor.js](public/js/editor.js).
- **Новая роль:** `ROLE_LEVEL` и `ROLE_NAMES` в [src/services/users.js](src/services/users.js) плюс миграция для CHECK-ограничения таблицы `users`.
