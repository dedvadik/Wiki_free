## Коротко

**WikiSpace** — база знаний в стиле Confluence. Это классическое серверное веб-приложение: HTML-страницы собираются на сервере из шаблонов, данные хранятся в PostgreSQL, а JavaScript в браузере только добавляет удобства (живой предпросмотр, горячие клавиши, переключатели). Сайт работает и с отключённым JavaScript.

| Слой | Технологии | Где в коде |
| --- | --- | --- |
| Веб-сервер | Node.js 22, Express 5, ES-модули | `src/server.js`, `src/app.js` |
| Шаблоны | EJS, серверный рендеринг | `views/` |
| База данных | PostgreSQL 17, драйвер `pg` | `src/db/` |
| Разметка статей | `marked` + `marked-highlight` + `highlight.js`, очистка `sanitize-html` | `src/services/markdown.js` |
| Сессии | `express-session` + `connect-pg-simple` (хранятся в PostgreSQL) | `src/app.js` |
| Безопасность | `helmet` (CSP), `bcryptjs`, собственный CSRF, `express-rate-limit` | `src/middleware/`, [Безопасность](page:Безопасность) |
| Загрузка файлов | `multer` | `src/routes/uploads.js` |
| LDAP / AD | `ldapts` | `src/services/ldap.js` |
| Сравнение версий | `diff` | `src/services/diff.js` |
| Упаковка | Docker, многоэтапная сборка, amd64 / arm64 / arm/v7 | `Dockerfile`, `docker-compose.yml` |

Всего около **9 000 строк** кода вместе с шаблонами и стилями.

## Принципы, на которых построен код

1. **Никаких нативных модулей.** Все зависимости на чистом JavaScript, поэтому один и тот же образ Docker собирается под любую архитектуру: сервер на x86, Mac на Apple Silicon, Raspberry Pi. Подробнее — [Развёртывание в Docker](page:Развёртывание в Docker).
2. **Прогрессивное улучшение.** Формы, меню (на `<details>`) и навигация работают без JavaScript; скрипты только добавляют удобство.
3. **Одно место для каждой настройки.** Инфраструктура (порт, БД, секреты) описана в `src/config.js`, поведение и внешний вид сайта — в схеме `SETTINGS_SCHEMA`. По этой схеме админка строит формы автоматически, см. [Настройки сайта](page:Настройки сайта).
4. **Тонкие маршруты, логика в сервисах.** Маршрут разбирает запрос и выбирает шаблон; работу с данными и правила делают модули `src/services/`.
5. **Безопасность по умолчанию.** Параметризованный SQL, очистка HTML, CSP, CSRF-токены, bcrypt. Небезопасный вариант нельзя включить случайно.
6. **Каждый файл прокомментирован.** В начале файла описано назначение модуля, перед каждым блоком — что он делает и почему именно так. Комментарии написаны по-русски.
7. **Кастомизация без правки кода.** Работает на трёх уровнях: админка, переменные окружения и папка `custom/` для переопределения шаблонов, стилей и тем.

## Структура репозитория

В корне — только файлы для запуска через Docker, весь код приложения — в папке `app/`. **Пути в этой документации (`src/…`, `views/…`, `public/…`) указаны относительно `app/`** — так же код лежит и внутри контейнера (`/app/src`, `/app/views`…).

```text
.
├── Dockerfile, docker-compose.yml, docker-bake.hcl   ← упаковка и запуск
├── .dockerignore, .env.example                       ← что не собирать, образец настроек
├── custom/              переопределения администратора (монтируется в контейнер)
└── app/                 ← ПРИЛОЖЕНИЕ
    ├── package.json     зависимости и скрипты npm
    ├── src/             серверный код
    │   ├── server.js        точка входа: подготовка, миграции, запуск, остановка
    │   ├── app.js           сборка Express: цепочка middleware и маршруты
    │   ├── config.js        все переменные окружения в одном месте
    │   ├── db/              пул соединений, миграции, SQL-схема
    │   ├── middleware/      авторизация, CSRF, общие переменные шаблонов, ошибки
    │   ├── routes/          обработчики адресов (по одному файлу на раздел)
    │   ├── services/        бизнес-логика: настройки, темы, Markdown, страницы,
    │   │                    пользователи, вход, LDAP, diff, CSS темы, первый запуск
    │   ├── utils/           HTTP-помощники, форматирование, SVG-иконки, форматы медиа
    │   ├── seed/            тексты демо-страниц для пустой базы
    │   └── tools/           служебные скрипты (импорт этой документации, данные для нагрузки)
    ├── views/           EJS-шаблоны страниц (partials/ — общие куски)
    ├── public/          статика: CSS, клиентский JS, иконки, темы оформления
    ├── docs/portal/     исходники этой документации
    └── tests/load/      нагрузочные тесты k6
```

## Как проходит запрос

```text
Браузер
  │  GET /pages/42
  ▼
helmet ─ защитные заголовки (CSP и др.)
  ▼
express.static ─ custom/public, затем public (CSS, JS, картинки, темы)
  ▼
разбор тела ─ формы и JSON
  ▼
express-session ─ cookie wiki.sid ↔ запись в таблице session
  ▼
flash → loadUser → locals → csrfProtection
  ▼
/healthz, /theme.css, /login, /register, /logout   ← доступны всегда
  ▼
siteAccess ─ «закрытая вики»: гостя отправит на вход
  ▼
маршрут (routes/pages.js) → сервисы (services/*) → PostgreSQL
  ▼
res.render('pages/show') → EJS → HTML
  ▼
404 / обработчик ошибок
```

Подробно каждый шаг описан на странице [Запуск и обработка запроса](page:Запуск и обработка запроса).
