JavaScript в браузере только улучшает интерфейс: сайт работает и без него. Все скрипты — отдельные файлы в `public/js/`, встроенных `<script>` нет, этого требует политика безопасности CSP.

## Файлы

| Файл | Где подключается | Назначение |
| --- | --- | --- |
| `theme-init.js` | в `<head>`, **синхронно** | выставляет светлый/тёмный режим до первой отрисовки |
| `app.js` | на всех страницах (`defer`) | общие улучшения интерфейса |
| `editor.js` | в редакторе страниц | редактор: визуальный и Markdown |
| `/vendor/turndown/…` | в редакторе, до `editor.js` | библиотека turndown (HTML → Markdown) из `node_modules`, без внешних CDN |
| `admin.js` | в разделах настроек сайта | поля цвета, пресеты, живой предпросмотр |

Скрипты находят элементы по **data-атрибутам** (`data-action`, `data-md`, `data-pref`, `data-editor-*`), а не по классам. Поэтому шаблон можно менять, не трогая JavaScript.

## theme-init.js

Написан на ES5 для максимальной совместимости. Читает `localStorage['color-mode']`, при его отсутствии — `data-default-mode` с `<html>`; значение `auto` разрешает через `matchMedia('(prefers-color-scheme: dark)')`. Итог записывается в атрибут `data-mode`.

## app.js

| № | Возможность | Как включается в разметке |
| --- | --- | --- |
| 1 | переключатель светлого/тёмного режима (кнопка ◐) | `data-action="toggle-theme"` |
| 2 | окно подтверждения перед отправкой формы | `<form data-confirm="Текст?">` |
| 3 | закрытие выпадающих меню кликом мимо и клавишей Esc | `<details class="dropdown">` |
| 4 | выезжающая боковая панель на телефоне | `data-action="toggle-sidebar"` |
| 5 | кнопка «Копировать» у блоков кода | автоматически в `.page-content pre` (только HTTPS или localhost) |
| 6 | подсветка текущего раздела в оглавлении при прокрутке | `IntersectionObserver` по заголовкам |
| 7 | печать | `data-action="print"` |
| 8 | настройки браузера на «Настройки → Оформление» | `<input data-pref="color-mode">`, `data-pref="editor-mode"`, `data-pref="editor-type"` |
| 9 | подгрузка свёрнутых веток дерева страниц | `<details data-tree-lazy="id">` → `GET /api/pages/:id/children` |

Настройки браузера применяются **сразу** без кнопки «Сохранить»: значение пишется в `localStorage`, а режим сразу меняется в атрибуте `data-mode`.

**Дерево страниц (п. 9).** Боковая панель не содержит все страницы пространства — сервер присылает только путь к открытой странице (`getSpaceTreeAround`, см. [Статьи](page:Статьи: разметка, дерево, версии, поиск)). Ветки, у которых есть дочерние страницы, но они не загружены, приходят свёрнутыми с атрибутом `data-tree-lazy`. Событие `toggle` у `<details>` не всплывает, поэтому один обработчик слушает его на фазе перехвата (`addEventListener('toggle', …, true)`) и работает и для веток, подгруженных позже. Ответ сервера — готовый HTML того же шаблона `partials/page-tree`.

## editor.js — визуальный и Markdown-редактор

У редактора два типа, переключатель «Визуальный / Markdown» — первая кнопка панели:

```text
Визуальный:
┌ [Визуальный|Markdown]  ¶ H2 H3 · B I S · • 1. ☑ ❝ · { } ▦ +▤ +▥ ― 📎 · ℹ️ ⚠️ 💡 🏷 ☰ ┐
│ редактируемая область (data-editor-visual, contenteditable) — выглядит как статья │
└───────────────────────────────────────────────────────────────────────────────────┘
Markdown:
┌ [Визуальный|Markdown]  H2 H3 · B I S …                     Текст | Оба | Просмотр ┐
│ textarea (data-editor-input)       │ предпросмотр (data-editor-preview)          │
└────────────────────────────────────┴─────────────────────────────────────────────┘
```

**Страница всегда хранится в Markdown**, в какой бы тип редактора её ни писали. Поэтому история версий, сравнение, поиск и экспорт `.md` одинаково работают для всех страниц, а тип можно переключать в любой момент:

| Переход | Что происходит |
| --- | --- |
| Markdown → визуальный | текст отправляется на `POST /api/preview` — сервер отрисовывает его **тем же кодом**, что и статью; HTML попадает в редактируемую область. Значки панелей, статусы и оглавление помечаются `contenteditable="false"` — их нельзя случайно «разломать» набором текста |
| визуальный → Markdown | HTML превращается обратно в Markdown библиотекой turndown (функция `createTurndown`). Стандартные правила знают заголовки, списки, ссылки, картинки, код; добавлены правила для зачёркивания, таблиц GFM (с выравниванием столбцов), пунктов списка («плотный» список остаётся плотным), пустых абзацев, чекбоксов задач и макросов `:::panel`, `{{status:…}}`, `[[toc]]` |
| сохранение из визуального | перед отправкой формы `syncVisualToMarkdown()` записывает Markdown в textarea — на сервер уходит обычная форма |

Преобразование выполняется, **только если текст в визуальном режиме меняли** (флаг `visualDirty`): просто посмотреть страницу в другом режиме — значит не изменить в ней ни символа. Все страницы этой документации и демо-страницы проходят круг «Markdown → визуальный → Markdown» без изменений в отрисованном результате — это проверялось в браузере автотестом.

В визуальном режиме форматирование работает через `document.execCommand` (как в Word): заголовки и цитата — `formatBlock`, жирный/курсив — `bold`/`italic`, списки — `insertUnorderedList`. Вставки браузерной командой `insertHTML` не делаются — она ненадёжна:

| Что вставляется | Функция | Как |
| --- | --- | --- |
| Блоки: таблица, блок кода, панели, список задач, линия, оглавление | `insertBlock` | прямо в DOM **после** абзаца с курсором (пустой абзац блок заменяет); после блока всегда остаётся абзац, чтобы писать дальше; курсор встаёт на текст-заглушку внутри блока. `insertHTML` вкладывал блоки внутрь абзаца (`<p><pre>`) и «съедал» абзац после них — дальше можно было писать только внутри панели |
| Строчные: статус, код в строке, ссылка, загруженная картинка | `insertInline` | через Range API точно в место курсора, курсор — сразу за вставкой. `insertHTML` клал неизменяемый статус (`contenteditable="false"`) после абзаца |

Такие вставки не попадают в историю Ctrl+Z браузера — удаляются выделением и Delete. Пустой редактор начинается с пустого абзаца (`<p><br></p>`), подсказку «Начните писать…» показывает класс `is-empty`. При сохранении неразрывные пробелы, которые браузер ставит при наборе, заменяются обычными. Кнопки «+▤ / +▥» добавляют строку/столбец в таблицу, где стоит курсор. Tab / Shift+Tab в списке — вложить/вынести пункт. Вставка из буфера очищается от чужих стилей (`cleanPastedHtml` оставляет только безопасные теги).

Какой тип открывается по умолчанию — выбирает администратор («Администрирование → Оформление → Интерфейс», атрибут `data-default-editor` у `<html>`); пользователь может переопределить это для своего браузера («Настройки → Оформление») или просто переключить в редакторе — выбор запоминается в `localStorage['editor-type']`. Если turndown не загрузился, остаётся только Markdown; без JavaScript — обычная textarea.

Возможности Markdown-режима:

| Возможность | Как сделано |
| --- | --- |
| Кнопки разметки | объект `ACTIONS`: `wrap` (обернуть выделение), `prefixLines` (префикс строкам), `insertBlock` (вставить блок); `textarea.setRangeText` сохраняет выделение |
| Горячие клавиши | Ctrl/⌘ + B, I, K; Tab — отступ; Ctrl+S — сохранить с любого места страницы (`form.requestSubmit()`) |
| Живой предпросмотр | `POST /api/preview` через 400 мс после последнего нажатия (debounce); предыдущий запрос отменяется `AbortController`; HTML приходит уже очищенным с сервера |
| Режимы вида | `data-mode` у `.editor-workspace`; выбор помнится в `localStorage['editor-mode']` |
| Тип редактора | `data-type` у `.editor-workspace` и `data-editor-type` у формы: CSS скрывает ненужное (`.markdown-only`, `.visual-only`) |
| Загрузка файлов | 📎, вставка из буфера (Ctrl+V), перетаскивание; в Markdown заглушка «Загрузка…» заменяется ссылкой из ответа, в визуальном сразу вставляется картинка или ссылка; id файла добавляется в скрытое поле `attachment_ids` |
| Защита от потери текста | `beforeunload` спрашивает «Покинуть страницу?», если есть несохранённые изменения |

Чтобы добавить кнопку, нужны `<button data-md="имя">` в `views/pages/form.ejs` и функция `имя` в `MARKDOWN_ACTIONS` и `VISUAL_ACTIONS`. Если кнопка нужна только в одном типе редактора, добавьте ей класс `markdown-only` или `visual-only`. Новый HTML-элемент в визуальном режиме должен уметь возвращаться в Markdown — для этого добавьте правило в `createTurndown()`.

## admin.js

- **Поля «цвет поверх темы»** состоят из палитры (без `name`) и текстового поля `#RRGGBB` (оно и отправляется). Скрипт синхронизирует их в обе стороны; кнопка «как в теме» очищает поле.
- **Цветовые пресеты** — кнопки с `data-preset='{"primary_color":"#…"}'`: заполняют поля, пустые значения очищают.
- **Живой предпросмотр**: пока настройки не сохранены, скрипт меняет CSS-переменные текущей страницы (`--primary`, `--header-bg`, `--header-text`); очищенное поле возвращает цвет темы.
